# Architecture decision records

One file per decision, numbered in the order they were taken. Numbers are never reused and files are never moved or archived; a decision that no longer holds keeps its file and gets `status: superseded` with a `superseded-by` link in its front matter. `amended-by` marks a decision that still holds except for one point, recorded in a newer ADR. New ADRs are drafted as `proposed`; only the maintainer sets `accepted` or `rejected`.

ADRs 0001 to 0009 are written in Chinese. This index gives each an English title and summary.

| ADR | Title | Status | Summary |
| --- | --- | --- | --- |

| [0002](0002-trainer-backend.md) | KohakuMossTrainer as an external training backend | accepted, amended by ADR-0015 | The trainer is never vendored or added as a submodule; the app clones it at runtime into `trainerRoot` and drives it as an external process with its own Python and Git environment. Its separate window was retired by 0015. |
| [0003](0003-launcher-first.md) | No own inference engine in V1; the launcher orchestrates runtimes | superseded by ADR-0009 | Shipped a launcher around the official Python runner first, to learn from real users before building an engine. Replaced when MossInfer became the engine. |

| [0013](0013-documentation-structure-and-language.md) | Documentation structure and language | proposed | Diátaxis folders plus `decisions/` and `records/`, English developer docs and Chinese user text, style guides by reference, MADR 4.0 with front-matter status, a header on every living doc, and `AGENTS.md` as the agent entry point. |
| [0014](0014-nightly-update-channel.md) | A nightly update channel signed by its own key | proposed | 每日构建 follows a signed `update-nightly.json`. | [0016](0016-external-agents-over-mcp.md) | External Agents use MossStudio over MCP through a capability registry | proposed | Off by default behind 设置 › 功能 › 外部 Agent: a loopback MCP server over a registry of about 80 actions, with an allowlist, approvals, path rules and an audit trail in main. | [0017](0017-studio-tool-hub-and-node-registry.md) | Register Studio nodes and workbench actions in source | proposed | Board tools are typed descriptors composed in the renderer and offered by one picker, 工具与节点, off by default behind 设置 › 功能 › 工具与节点管理器. The picker reuses the board's own callbacks and undo steps, registers nothing with the 助手 or MCP, and shares the right sidebar between 助手 and 解析 without dropping a chat. |
